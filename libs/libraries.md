# Libraries

This folder contains all the external and internal libraries used by the project.

## Structure

Each library is organized into its own subfolder for clarity and modularity.  
Libraries may include source code, headers, or precompiled binaries as needed.

## Purpose

- Provide reusable code modules.
- Keep external dependencies isolated.
- Maintain a clean, scalable project structure.

## Notes

- Internal libraries developed under XtremeStudios should follow project coding standards.
- External libraries should not be modified directly.  
  If changes are needed, fork and maintain separately.
- Keep library versions documented for consistency.

---

## Included Libraries

### 1. CodeFrame

**Description:**  
The official reusable utility and foundation library shipped with every project generated by CodeFrame.

**Features:**  
- ✨ Core utilities for strings, arrays, objects, types, and async flows
- ⚙️ Shared configuration and type systems
- 🔧 Designed to plug directly into any CodeFrame-generated project
- 📦 Lightweight, dependency-free (XPM-compatible)
- 🧠 Clean, composable, and engineered for long-term scale

**Notes:**  
CodeFrame is considered a core system and should not be removed or replaced.  
All projects assume its presence for foundational operations.

## Library Guidelines

- Internal libraries should follow XtremeStudios code standards and practices.
- External libraries must be versioned and documented.
- Do not modify external libraries directly — fork if changes are necessary.
- Keep this document updated as libraries are added, upgraded, or deprecated.
